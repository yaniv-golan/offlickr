# offlickr v0.1.1 — Maintenance

**TL;DR:** a supply-chain and CI maintenance release. If v0.1.0 works for you,
nothing about your archives changes — but the project's dependency and workflow
hygiene is now clean.

## What's new

Nothing user-facing. The ingest, derive, render, and fetch stages, the
`minimal-archive` theme, and the generated site are byte-for-byte equivalent to
v0.1.0.

## Fixes

- No user-visible bug fixes. The only source change since v0.1.0 is an
  explanatory comment on the optional-HEIF import guard in
  `offlickr/derive/images.py`.

## Security

- Every advisory `pip-audit` reported against the lockfile is cleared: `pillow`
  12.3.0, `click` 8.4.2, `urllib3` 2.7.0, `idna` 3.15, `soupsieve` 2.8.4,
  `msgpack` 1.2.1, `pip` 26.1.2.

  Worth being precise about who this helps: these are `uv.lock` updates. They
  matter if you develop offlickr, run its CI, or install from the lockfile. If
  you installed from PyPI, your resolver was already free to pick the fixed
  versions, because every constraint in `pyproject.toml` is a lower bound
  (`pillow>=10.3`, `click>=8.1`, …) and those constraints did not change in this
  release.

- All GitHub Actions are pinned to commit SHAs, and workflow `permissions` are
  scoped to the individual jobs that need them, closing the outstanding
  OpenSSF Scorecard and CodeQL alerts.

## Breaking changes

- None.

## Upgrade instructions

```bash
pipx upgrade offlickr
# or
uv tool upgrade offlickr
```

Upgrading is optional for end users — see the note under *Security* above.
